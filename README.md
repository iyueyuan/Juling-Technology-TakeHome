# 储物间矩形物体布局求解器

给定一个房间轮廓多边形、一扇门，以及若干可旋转的矩形物体（冰箱 / 货架 / 离地架 / 制冰机），在满足「全部在轮廓内、互不重叠、不遮挡门、冰箱开门边留净空、旋转与轮廓边平行或垂直」的前提下，求出每个物体的中心点坐标与旋转角，并**优先让所有物体贴墙摆放**。

- 输入目录：`Input/`（`example1..4.json` 为题目给定输入，`image01..04.png` 为参考图纸）
- 输出目录：`Output/`（每个样例一个 `*.result.json`，以及布局图、校验报告、汇总表）
- 代码目录：`solve/`（纯 Python 标准库实现，`Pillow` 仅用于出图，可选）

---

## 1. 核心代码实现逻辑说明

### 1.1 数据模型与输入解析（`solve/model.py`）

- 输入 JSON 字段：`boundary`（轮廓点序列）、`door`（门两端点）、`isOpenInward`（是否内开门）、`algoToPlace`（物品名 → `[length, width]`）。
- 物品类型由名称前缀推断（`fridge`/`iceMaker`/`shelf`/`overShelf`，大小写不敏感）。
- 单位统一为毫米（与图纸标注的 m² 面积核对一致）。

### 1.2 几何内核（`solve/geom.py`，纯标准库）

关键点（都针对本题的坑做了专门处理）：

- **定点清理 `polygon_cleanup`**：循环执行「去重复顶点 → 去反向尖刺（退化的往复边）→ 合并共线边」直到收敛。`example4` 的输入多边形**末点等于第 2 个点、首末边反向重叠（自交）**，正是靠这一步还原成简单多边形（清理前后面积不变）。
- **内侧法线 `interior_normal`**：用「偏移 1 mm 的探针点是否在房间内」判定方向，**不假设多边形的顺/逆时针**。`example1`、`example3` 的边界是顺时针，`example2`、`example4` 是逆时针，混合输入也能正确处理（这是参考实现里最常见的翻车点之一）。
- **矩形判据**：`rect_inside_polygon`（四角在内 + 边不真穿越 + 边中点在内 + **多边形任意一条边都不得从矩形内部穿过**——最后一条专门挡 `example4` 那种「100 mm 窄缝被物体横跨」的情形）、`convex_overlap_area`（Sutherland–Hodgman 精确求交叠面积）、`segment_overlap_with_rect`（门洞/开门边的零深度判据）、`wall_contact`（贴墙接触长度）。
- **容差**：贴合允许 `1e-6 mm`；交叠面积阈值 `1e-3 mm²`（求解器，精确坐标）；校验器对序列化取整放宽到 `1 mm²`、出界 `0.01 mm`（见 §1.6）。

### 1.3 朝向集合（H3：与轮廓边平行或垂直）

- **默认 `--orientation auto`**：把每条轮廓边方向按 mod 90° 聚类（容差 1°，簇内总墙长 ≥ 500 mm 才纳入，代表角在 0.5° 内吸附到 0°/90°），允许角 = 聚类代表角及其 +90°。这样物体对**任意**轮廓边（含斜墙）都能做到平行或垂直：`example1` 的允许角是 {0°, 90°, 15.852°, 105.852°}，其中 15.852° 正是该房间那堵斜墙的方向（实测物体与该墙平行的偏差为 0.000°）；`example2/3/4` 没有斜墙，结果只用 0°/90°。
- **"斜向"不是任意角度**：它只是"与斜墙平行"，允许角始终来自真实的墙方向，只有 4 个离散值。
- 求解时物体使用**每条边各自的精确角度**（而不是聚类的平均值），避免斜墙贴边时出现亚毫米的误差。
- `--orientation axis`（可选）限定只用 0°/90°。两种模式都满足题目「与轮廓边平行或垂直」；差别只在能否贴斜墙：`example1` 默认（auto）8/8 贴墙，`axis` 只有 4/8。

### 1.4 净空规则（全部按题目口径）

| 规则 | 实现 |
|---|---|
| 内开门 | 门宽 N × N 的内侧方形禁区（题目明示「内开门会占据 N×N 的空间，N 为门的宽度」） |
| 外开门 | **零深度精确判据**：任何物体与门洞开口线段「正长度重合」即违规（即不得齐墙压住门洞；只在门端点碰一下是合法的），不外造余量 |
| 冰箱开门边 | 开门面 = **面宽等于 `length` 的那条面**；该面之前净空深度 = **冰箱门宽 = `length/2` = 610 mm**（本题冰箱是四门，单扇门宽 1220/2，沿用题目「净空深度 = 门的宽度」的口径）。净空带必须完整落在房间内、且不含任何其他物体 |
| 货架 / 离地架 | 四边均可贴放物品（无净空要求，贴靠合法） |

所有净空带都登记为「障碍物」，与已放物体同级参与碰撞检测，**对后续每个物体都生效**。

### 1.5 候选生成 + 搜索（`solve/solver.py`）

1. **候选生成（解析几何，非栅格）**
   - **A 墙锚定**：每条边 × 允许角，矩形一边贴墙（用内侧法线保证贴在内侧），沿墙按 `wall_step`（默认 100 mm）密集采样 + 顶点/门投影锚点。
   - **B 物体锚定**：贴合最近一个已放物体的边滑动（用于紧贴排列）。
   - **C 内部粗栅格回退**：仅在墙+物体锚定找不到解时启用（50 mm 步长 × 允许角，取前若干）。
2. **打分（字典序最大化）**：① 贴墙物体数 → ② 贴墙接触总长 → ③ 与已放物体接触总长 → ④ 中心到墙距离（越小越好）→ ⑤ 冰箱朝向门 → ⑥ 坐标字典序（保证可复现）。
3. **搜索**：**beam search** 为主（宽 40，跨墙交错采样保持多样性）；若仍有物体没贴墙，再做一次确定性的**贴墙修复**（逐个尝试把未贴墙的物体挪到墙上），最后用**节点数有界的 DFS** 兜底（既能补可行性，也能改善贴墙数；`--dfs-nodes 0` 可关闭）。全过程只用节点/规模预算、不用时间预算，因此结果**每次运行完全一致**。
4. **口径回退**：若某样例在 `length/2` 净空下确实无解，自动改用「纯题面 0 mm 净空」重试，并在结果中标注 `clearanceMode`，**绝不给出误导性的「不可行」结论**。

### 1.6 独立校验器（`solve/validator.py`，验证题目的要求）

校验器**不依赖求解器内部状态**，只吃「原始输入 + 结果 JSON」重新计算，逐条输出 PASS/FAIL 与实测值：

> **边界说明（诚实起见）**：校验器与求解器**共用同一套几何内核**（`geom.py`），所以内核判据本身的错误会同时骗过两边——提交前的最终验收就抓到过一例：`example4` 的 100 mm 窄缝被 `shelf-1` 横跨（约 98000 mm² 露在房间外），当时两边一起漏判。因此内核层面另有把关：① 单元测试（含窄缝判据、退化多边形清理、贴墙接触长度等回归）；② **用独立实现交叉验证**——分离轴（SAT）判两两重叠、稠密采样判越界、PIL 栅格化复核、出图的像素级检查，四者的结论与 V1–V8 一致。

| 编号 | 规则 |
|---|---|
| V1 | 轮廓有效性（清理掉的退化顶点、面积>0、简单多边形） |
| V2 | 全部物体在轮廓内（容差 0.01 mm，吸收输出的取整误差；含「矩形不得横跨窄缝」判据） |
| V3 | 两两不重叠（交叠面积 ≤ 1 mm²，允许贴合） |
| V4 | 每个角度与某条轮廓边平行/垂直（≤ 0.5°） |
| V5 | 门未被遮挡（内开 N×N 无物体；外开不压门洞） |
| V6 | 冰箱开门边前方 610 mm 净空在房间内且无任何物体 |
| V7 | 货架/离地架允许贴放（贴靠不算重叠，不误报） |
| V8 | 完整性（数量/名称/尺寸一一对应、坐标有限） |

附加指标：贴墙物体数、贴墙总长、自由面积、冰箱净空深度。

### 1.7 复杂度与「是否可行」的表述边界

- 几何判定为 O(边数 × 物体数)；搜索以 beam 为主（并行保留 40 条状态），单样例约 1~14 秒，四例合计约 15~20 秒（随机器负载波动；`example2` 会用到 DFS 兜底，占掉大部分时间）。
- **诚实性说明**：搜索到合法解 → `feasible=true`（构造性证明，且被独立校验器复核）；搜索不到 → `feasible=false` 且状态为「在给定预算内未找到」，并附诊断（面积/候选数/放宽约束后的结果），**不声称已证明不可行**。矩形装箱本身是 NP-hard，本实现是启发式而非精确求解器。

### 1.8 数据流与布局示意图（`Output/figures/*.layout.png`）

```
Input/exampleN.json                 程序计算                        产出
 boundary  (房间轮廓)        solver.solve()  ───────►  Output/exampleN.result.json
 door      (门的位置/宽度)         │                    （每个物体的【中心点 + 旋转角】）
 isOpenInward                     │
 algoToPlace (各物品长宽)          └──► render.py  ───►  Output/figures/exampleN.layout.png
                                       （按算出的坐标/角度画矩形，外加房间轮廓、门、净空带）
```

- **程序不读输入的 CAD 图纸**（`Input/image01..04.png`）：那 4 张图只是给人看的参考底图。把它们删掉，程序照样运行、照样出图。
- **图 = 求解结果的示意图**：房间轮廓、门、物品尺寸都直接来自输入 JSON（一个字都没改），而**每个物体的中心点与旋转角是程序算出来的**——这正是题目要求的输出。因此图与 CAD 图纸"轮廓像、摆放不像"：轮廓同源，摆放是算法排的另一版合法解（装箱问题解不唯一）。
- 图上元素：深色多边形＝房间轮廓（`example4` 会额外用细灰线叠出**原始退化边界**）；红色粗标记＝门（**向房间内偏移**，其外沿恰好是门洞线）；浅红方块＝内开门的 N×N 禁区；橙色矩形＝冰箱开门边净空（**只画生效那一侧**，即落在房间内的那条）；彩色矩形＝物品（冰箱=蓝 / 制冰机=紫 / 货架=绿 / 离地架=黄），中间标 `名称 / 长x宽`。
- 图上**不写中文**：PIL 的默认字体只覆盖拉丁字符集，写中文会渲染成"豆腐块"，所以配色含义只在本节说明。物件标签是 ASCII，正常显示。
- 出图是**可选**的：只依赖可选的 `Pillow`；未安装时打印 `Pillow not installed; skipping PNG render.` 并跳过，求解与校验完全不受影响。触发方式见 §2（`run_examples.py`、`solve.py --batch`、`solve.py --render-dir`；`validate.py` 不出图）。目录会自动创建，删掉 `Output/figures/` 后重跑会逐字节重新生成同样的图。
- 图与校验的关系：校验器只检查**物体本体**（在轮廓内 / 不重叠 / 贴墙 / 不挡门 / 冰箱净空被挡）。图上"门标记""净空带"这类装饰元素已保证**不会画到轮廓之外**——门改成向内偏移的标记，净空带只画生效侧；并有像素级回归测试 `solve/tests/test_render.py` 守着（逐像素反算坐标，要求落在房间外的橙/红像素为 0）。

## 2. 运行环境及运行方式

- 环境：**Python 3.7+**（本机实测通过 **3.10.11** 与 **3.12.14**）。只用标准库；最低版本由 `dataclasses` 与 `from __future__ import annotations` 决定（均为 3.7 引入），代码里没有用到 3.8/3.9 之后才有的 API。出图需要可选依赖 `Pillow`（`pip install pillow`），不装则自动跳过出图、其余功能不受影响。
- 目录：代码在 `solve/`，输入在 `Input/`，结果在 `Output/`。

```bash
# 一键：对 Input/ 下所有输入 求解 → 校验 → 出图 → 汇总
python solve/run_examples.py --input Input --output Output

# 单个样例求解
python solve/solve.py Input/example1.json -o Output/example1.result.json

# 批量求解（等价于 run_examples 的求解部分）
python solve/solve.py --batch Input/ -o Output/

# 独立校验 Output/ 下的全部结果 JSON（按 exampleN.result.json ↔ exampleN.json 配对）
python solve/validate.py Input Output

# 单元测试（19 个：几何不变量与窄缝判据 / 校验器负样例 / 端到端 + 确定性回归 + 不可行输入 / 出图像素级检查）
python -m unittest discover -s solve/tests -t .
```

常用参数（`solve.py` / `run_examples.py`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--fridge-front-clearance-mm` | `length/2`（本题 610） | 冰箱开门边净空深度；`0`=纯题面，`300/610/800/1220` 可复现各参考实现 |
| `--orientation` | `auto` | `auto`=允许与任意轮廓边（含斜墙）平行/垂直；`axis`=只允许 0°/90° |
| `--beam` | `40` | beam 搜索宽度 |
| `--dfs-nodes` | `15000` | DFS 兜底/质量步的节点上限；设为 `0` 则完全关闭 DFS（更快） |
| `--time-limit` | `25` | 单样例时间上限（秒，仅作安全阀；正常不触发，故不影响复现性） |
| `--wall-step` | `100` | 沿墙采样步长（mm） |
| `--seed` | `0` | 随机种子（回退阶段用，保证可复现） |

**净空参数对照**（为什么取 610 = length/2，见 1.4）：公开同类实现里冰箱净空取了 300 / 610 / 800 / 1220 不等，其中还有把开门边取反、或净空带未生效的实现；本实现按题目「净空深度 = 门的宽度」口径，四门冰箱单扇门宽即 `length/2`。

### 2. AI 主要帮助了哪些部分
- **思路拆解**：把题目拆成「几何内核 → 朝向聚类 → 候选生成 → 搜索 → 独立校验器」几层；并先做输入勘察（多边形是否自交、门落在哪条边、边方向有几簇、单位与面积核对、物品面积占比）。
- **代码生成**：`solve/` 下全部代码 —— 几何内核（`geom.py`）、输入解析与数据模型（`model.py`）、求解器（`solver.py`）、独立校验器（`validator.py`）、出图（`render.py`）、CLI 与三个入口、单元测试。
- **Debug**，定位并修复了：
  1. **斜墙角度精度**：物体角度若取「边方向聚类的平均值」，与墙的精确角度差一点点，就会导致物体亚毫米越界，`example1` 的冰箱候选一度几乎为空；改为「按每条边的精确角度生成候选」后解决。
  2. **交叠面积计算的符号错误**：凸多边形裁剪（Sutherland–Hodgman）求交点的公式少了一个负号，导致重叠面积被严重低估、求解器放过真实重叠；修正后重叠被正确检出。
  3. **内法线方向**：`example1`/`example3` 的轮廓是顺时针，若假设逆时针会导致贴墙候选全部失效；改为用「偏移 1 mm 的探针点」判定内侧。
  4. **序列化取整误差**：输出坐标取整到 0.001 mm 后会产生亚毫米级「越界/重叠」，需要在校验器里用合适容差吸收。
  5. **窄缝被横跨（最后验收时才发现）**：`example4` 的输入里有一条 100 mm × 1000 mm 的窄缝，`rect_inside_polygon` 原先只查「四角 + 边中点 + 边真交叉」，而窄缝的墙恰好与物体的一条边共线、所有检查点都落在墙线上，于是判为「在内」，求解器把 `shelf-1` 摆成了横跨窄缝（约 98000 mm² 露在房间外），校验器 V2 也一起误判通过。补上「多边形任意一条边不得从矩形内部穿过」的判据后解决，并加了针对该窄缝的回归测试。
- **参考实现调研**：对比 4 个公开仓库对「门 / 冰箱净空」的不同处理，并指出它们各自的实现缺陷（碰撞阈值过松导致真实重叠、冰箱净空带未登记为障碍或是死代码、冰箱开门边取反、内开门只留 N/2 而非 N×N）。

### 3. 哪些关键逻辑是我自己理解并调整的
- **净空口径是我自己一步步问出来并定下的**：我先问净空是什么意思，再确认是不是冰箱门前那块区域，最后提出应该和冰箱门的宽度有关——据此才定下**冰箱开门边净空 = 冰箱门宽 = `length/2` = 610 mm**（本题为四门冰箱，单扇门宽 1220/2），把方案从 AI 自造的 800 / 1220 等数值纠正回题目口径；同时明确**内开门按题目的 N×N（N 为门宽）、外开门用不得与门洞正长度重合的零深度判据**，不自造余量。
